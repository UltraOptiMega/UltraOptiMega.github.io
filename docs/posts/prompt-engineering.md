# Prompt Engineering 实战心得

写了一段时间的提示词，总结几个核心原则。

## 清晰比聪明更重要

很多人喜欢用复杂的措辞来写 prompt，但实际上模型对**简洁、结构化**的指令响应更好。

```text
# 角色
你是一个专业的代码审查员。

# 任务
审查以下代码，重点关注：
1. 潜在的安全漏洞
2. 性能问题
3. 代码可读性
```

## 给模型思考的空间

对于复杂任务，让模型先输出推理过程，再给出结论，准确率会显著提升。

> Chain-of-Thought 不是噱头，是真实有效的工程技巧。

## 迭代比一次到位更现实

好的 prompt 都是改出来的，不要指望一次就完美。
